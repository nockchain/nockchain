# OSS-NEXT execution plan

Consolidated, deduplicated execution plan for `docs/native-compiler/OSS-NEXT.md`: fix the items in `docs/native-compiler/TODOS.md` and `docs/native-compiler/TODOS-PERF.md`, eliminate the overhead this branch inflicted on `nockvm`, conform `honk` to post-PMA `nockvm` memory-safety, parity-check honk artifacts against the hoonc-built kernels in `assets/*.jam` (read-only — never rebuilt; the dir-hash leaf is expected to differ outside Bazel sandboxing), and keep honk's roswell compile under 60 seconds.

## Decisions

Hint-blind jet matching (find_jet normalization, Warm double-insert, Batteries::matches structural fallback) becomes opt-in, gated to honk via a runtime `JetDispatchMode` on `Context`; hoonc/nockchain revert to exact master dispatch behavior, and honk's hint-blind path gains memoization via alias insertion into the warm table. Parity covers all six kernels (dumb, wal, miner, peek, bridge, roswell) with the dir-hash leaf as the only tolerated difference. Deferred to follow-ups: the ut/mod.rs split (TODOS #14), find/fend/fund/fond parity matrices (TODOS #15), and hoonc-oracle fixtures for the strict compiler_mint tests (TODOS #11). PMA cold-state sharing (SLAB-PMA-COMINGLING Phase 4) stays in scope, sequenced last with an escape hatch. Honk-side perf work is demand-driven against the 60s roswell budget: small obviously-correct items land unconditionally, deeper items only if the gate fails. The behavior-event/parquet trace stack is deleted per the Instructions section of LOG-HINT-EVENT.md.

## Track H — honk parity, correctness, conformance

> ROSWELL RESOLVED (2026-06-12): the roswell `redo-match` is the documented unsound cross-call `miss`-memo persistence (`Ut::miss`), which `compile_entry` wrongly enabled for entry/kernel compiles despite `miss()`'s own comment stating entry compiles drift and must use per-call memos. ## H2 cache-soundness audit + fix (2026-06-13)

A multi-agent adversarial audit of every honk type-checker cache/memo surface found 7 with the roswell-class latent miscompile (key omits active %rest/%hold fan_context_key): mint, mull, redo, rest, fish, nest, crop+fuse. All were widened to carry fan_context_key (mint/mull also carry the arm_epoch/placeholder memo context, matching the sibling core_mint cache). All widenings are output-safe (every kernel stays byte-exact; the context fields collapse to 0 in the steady state, so the key only adds misses where the result genuinely depends on context the mugs don't capture). Two existing tests (active_rest_fan_context_partitions_context_sensitive_native_ut_caches, …_does_not_partition_rest_boundary) encoded the bug by asserting cross-fan cache hits; flipped to assert the correct partition. The audit confirmed musk mack caches are sound (no change).

ACCEPTED TRADEOFF (user decision): the extra misses push roswell from 53s to ~75s, over the 60s gate. Per user direction, the hardening ships over-gate; recovering <60s is a follow-up via the deferred H4 perf work (per-batch directory-mug cache, SourceFile read/parse cache) which the plan scoped as demand-driven against this budget. Measured points (quiet machine, all byte-exact): narrow 53s, fan-only 68s, fan+arm-epoch 75s.

FOLLOW-UPS surfaced by the audit (not yet done): (Step 4) bran_semi key omits the non-hold portion of the seen_raw recursion guard — latent, no reaching case constructed, but matches a documented requirement; (Step 6) the ArmMemoSet cache surface is entirely unwired and the placeholder_context_key is permanently 0 (dead set) — remove the dead recursion-naive scaffolding (the exact shape that caused the roswell miss-memo bug when wired) or wire it deliberately; (perf) the H4 dir-mug + SourceFile caches to bring roswell back under 60s.

## H3 native-parity audit finding (2026-06-13)

Added HONK_NATIVE_PARITY (env gate, off by default, output-neutral when off): when set, the canonical hoon-138 build does NOT substitute hoonc's embedded prelude formula / subject-type — honk mints them natively — to expose whether honk's own +mint of the prelude matches the spec compiler rather than passing parity by importing hoonc-produced nouns. (Cold state and the canonical $octs input are kept; they are jet-registration / data inputs, not compiler artifacts.)

RESULT: native prelude mint is currently IMPRACTICAL — compiling dumb with HONK_NATIVE_PARITY=1 ran ~49 minutes and was OOM-killed (rc=137) before producing output. So the embedded hoonc prelude formula/type is a NECESSARY bootstrapping shortcut, not merely a parity mask: honk natively compiles application code (all six kernels byte-exact) but cannot natively re-mint the full standard-library prelude in available time/memory. The audit is therefore INCONCLUSIVE on native-mint correctness (it cannot complete); it surfaces no application-layer correctness disparity. Whether the blowup is a pathological (quadratic/exponential) cost or an outright non-termination in honk's native mint of the largest input is an open question for a future profiling pass — it is a perf/bootstrap wall, not a fixed correctness bug, and is out of scope for the correctness-first pass (the kernels are byte-exact). The gate is retained as the audit/experimental tool for that future native-self-hosting work.

## H5 branded eval boundary — primitives + first call site (2026-06-13)

Resolved the user's "no sui-generis Noun APIs in honk" constraint for the eval boundary by reusing the generative BrandedNounSpace (their commit 9c2cc035) instead of inventing a honk-local wrapper. BrandedNounSpace is generic over NounSpace and read-only; the eval boundary needs two write-side ops it can't express, so they live in nockapp (where the copy primitive and interpreter both are), not honk. (1) NounSlab::with_brand — slab-side entry to the branded space (the machinery already applied to slabs via noun_space(); only the convenience method was missing). (2) BrandedNounSpaceExt::copy_in / copy_in_handle — copy a foreign noun into a branded arena, returning a handle branded to that arena; the only way to obtain a branded handle for a foreign noun. (3) BrandedEvalExt::interpret — evaluate a branded formula against a branded subject (both carrying the eval arena's brand), returning a branded product; a raw slab noun can't reach interpret without a brand mismatch. (4) BrandedNounHandle::unbranded (nockvm) — the single deliberate brand exit. The (allocator, space) pairing can't be proven by types (distinct values), so it's debug-checked by resolving the copy against the space; release trusts it (matching NounSpace's identity fast path), so the migration carries ZERO release cost. Commits 79b2ff4e, bc4fd0a9.

First concrete call-site migration (dfe391ab): eval_formula_noun_in_context — the canonical mint/eval path — now brands the interpreter stack and routes copy + interpret through the branded ops; the raw slab formula no longer type-checks as an interpret argument. Verified byte-exact: dumb and roswell kernels both PASS (exact) vs the hoonc reference through the migrated path; honk 181/181 in debug (exercising the debug-only provenance cross-checks on every eval); roswell timing unchanged (~76s, same H2 over-gate regime).

## H5 fit assessment — how far brands actually help honk (2026-06-13, 10-agent adversarial audit)

Verdict: YES-NARROWLY. The branded API is a real, type-enforced win on exactly ONE hazard class and is inert or obstructive everywhere else honk spends its risk budget. HELPS (high value): the slab-noun-reaches-interpret boundary — honk's single highest-severity bug class (runtime pointer-range panic in debug / wrong-arena resolution in release) becomes a compile-time brand mismatch. Already live at eval_formula_noun_in_context; 3-4 structurally identical single-scope candidates remain (slam_wrapper_gate honk.rs:2069-2108 interpret@2084; eval_standard_formula_to_jam interpret@2205) — mechanical to migrate. DOES NOT HELP (use a different tool): (1) ~199 as_raw/raw_equals cache-identity sites — the largest unsafe category, all single-arena in ut.slab, soundness already covered by the noun_eq structural fallback; brands disclaim value equality and expose no key, so they are inert here. (2) Musk *mut NounSlab / *mut Context self-aliasing (ut/mod.rs:5780-5848) — this is borrow-checker avoidance / mutable self-aliasing, NOT provenance; a Copy read-only brand cannot represent &mut to the stack/slab. Real fix is struct-level borrow-splitting (MuskRuntime method taking &mut NounSlab explicitly); brands can only decorate the copy-out AFTER that restructure. (3) The Box::leak'd 'static Ut slab + raw Nouns stored across compile calls in Compiled and ~30 Ut caches — the brand's core no-escape rule (handles cannot leave with_brand, be stored in a field/map, or be 'static) FIGHTS this architecture head-on; broad adoption would forbid the caches, not protect them. (4) set_mug in-place mutation, restore_checkpoint positional rollback, with_stack_frame Preserve contract — pure lifetime/mutation invariants the read-only brand does not touch (the migrated brand even lives INSIDE the still-unsafe with_stack_frame). (5) Cons-ing formerly-foreign nouns (vase builders) — copy_in brings sources in as read-only handles, but you must unbranded() both to T(...) them, so the dangerous adjacency happens unbranded; no branded cell-builder exists. CAVEATS: the brand's runtime checks are #[cfg(debug_assertions)] and release-skipped for the rangeless native slab, so the value is the COMPILE-TIME guarantee, not release defense; and every persisted eval product must unbranded() (dropping the guarantee) to be stored — so this is scoped, not end-to-end, safety. RECOMMENDATION: keep the migrated site, extend to the 2-3 identical single-scope eval boundaries, and STOP. Do not brand Ut's return-and-cache flow broadly (high churn, zero safety, fights the leaked-static architecture). For the rest use the right lever: borrow-splitting for musk; a safe NounSpace identity/interning token for the as_raw sites (nockvm-side, orthogonal to branding); an H6-style contains_alloc_ptr check inside copy_into NOT gated on debug_assertions if release-mode boundary defense is wanted (a better lever than the brand, whose checks are release-skipped). This supersedes the original H5 framing that treated brands as the mechanism for "every interpret call site" — the musk sites need borrow-splitting first, and the broad slab/cache surface is out of brand scope entirely.

(copy_into dedupes), clear the build caches, `rewind_to` the working slab —
then mint the next layer against the carried subject, composing formulas
exactly as `=>` does (q-formula with p-formula as subject). Working-set memory
then bounds to one layer + the frozen subject instead of the cumulative whole.

1. Clearing caches at a layer boundary drops `lazy_resolvers`. mint_core builds
   FULL batteries (semi_noun_full), and cross-layer name resolution reads the

   cores — BUT this must be proven byte-exact; any blocked-battery

   first.
2. The chunked formula must be byte-identical to the monolithic mint's, or

3. Only chunk at the TOP-LEVEL layers — inner `=>`s are mid-expression (no
   unwound boundary) and must keep using the normal recursive mint.

Alternative (heavier): full compaction — copy all live roots to a fresh slab
through one shared forwarding map and rebuild the raw-pointer cache keys —
which also works mid-process but requires enumerating + remapping every cache

## Step 2 — intra-core chunking ruled out; the giant core needs a reclaiming arena (2026-06-15)

Investigated whether the dominant stdlib core (layer 7, ~the whole compiler) could be chunked per-arm. It can't usefully: build_arms_battery_from_map mints each arm via build_arm_formula_direct against the LAZY core_type, so a reference to a sibling arm re-resolves that arm's TYPE on demand through the lazy resolver (re-play). In a densely cross-referential core like ++ut, minting any single arm pulls in (re-plays) a large fraction of the core's types — so reclaiming between arms would NOT bound the per-arm peak (it approaches the whole-core type graph) and would pile on heavy recompute (re-playing dependency types per arm). So per-arm chunking is both ineffective and slow.

DEFINITIVE Step-2 conclusion:
- Reclamation primitive (NounSlab checkpoint/rewind): built + tested.
- Chunked-mint mechanism: byte-exact on the synthetic `=>` chain (cross-layer resolution survives fresh per-layer Uts).
- Top-level `=>` chunking of the prelude: WIRED + measured — reclaims 6/7 layers (~4 GB through them) but the 7th (giant stdlib core) is one monolithic mint that climbs linearly (>23 GB); top-level chunking is necessary but insufficient.
- Intra-core per-arm chunking: RULED OUT (lazy re-play pulls in a large fraction of the core per arm; no bound + heavy recompute).

So the giant core fundamentally needs to be type-checked largely together, and the ONLY route that bounds it is a reclaiming ARENA within the mint — the canonical Vere model: a NockStack-style frame arena where per-arm scratch is reclaimed at frame-pop while the shared core type stays live, with cheap re-play via memoization + structural sharing. For honk that is the large H7-class refactor: run Ut over a frame-popping allocator AND re-key/stack-localize the ~200 as_raw() cache keys AND re-express lazy_resolvers as in-noun captured gates (canonical ++laze) — the same out-of-slab-reference problem flagged from the start, now confirmed as the unavoidable core of native self-hosting. Plus dbug spot-stack preservation for byte-exactness.

RECOMMENDATION: ship the hybrid (embedded prelude). Native self-hosting of hoon-138 is gated on the frame-arena refactor (large, H7-class), not on chunking — chunking handles the layer chain but cannot bound the one giant core. The chunking infrastructure built here (primitive + driver + peel + synthetic test) remains useful (e.g. bounding multi-unit/batch builds and as the frame-arena substrate's checkpoint/rewind), and is left in place for review.

## H7 frame-arena refactor — design locked (2026-06-15)

Goal: bound honk's compile memory (giant stdlib core climbs linearly >23 GB) and recover runtime, by reclaiming per-arm scratch while keeping the shared core type + accumulated battery live. Four reconnaissance maps (cache inventory, lazy-resolver lifecycle, arm-mint escape analysis, NounSlab+NockStack APIs) produced these load-bearing facts and the design below.

Load-bearing facts:
- One arena: Ut.slab is a single &mut NounSlab; every constructor (T/D/cons/comb/ty_core/...) allocates into it. A bump allocator cannot preserve-down in place (no NockStack double-ended frame trick).
- Per-arm frame boundary = build_arm_formula_direct (mod.rs ~7316). It returns ONLY the arm formula; the arm type is discarded scratch (prune_recursive_holds result bound to _ty). The battery is accumulated incrementally in the CALLER build_arms_battery_from_map via T(slab,[formula,...]) — so each arm's formula must be preserved into keep before its frame pops.
- Shared anchor = core_type_lazy, built once in mint_core, held in lazy_resolvers for the whole Ut (deliberately never cleared). Must live in keep.
- Cross-arm sharing happens through the lazy resolver: cached_formula_by_axis is keyed by integer AXIS (frame-safe key); only its value Noun is scratch-resident. Preserve that value to keep on insert and cross-arm reuse survives reclamation WITHOUT O(arms^2) re-mint. This is what makes per-arm reclamation viable (vs the ruled-out fresh-Ut chunking).
- Cache hazard: ~20 caches are pointer-keyed and/or hold scratch-resident Noun values (mod.rs: mack_core_cache_raw, mack_cache_raw, hoon_cache_raw, decoded_hold_hoon_cache_raw/_ptr_cache, hoon_ast_ptr_cache, open_cache, burp_type_cache, hold_repo_fan_leg_raw_ids/_id_by_hold_raw; types.rs memo *_raw variants + nest/mint/mull/etc whose VALUES are minted nouns). On frame pop these dangle, and recycled scratch addresses could false-hit pointer-keyed entries (a correctness bug, not just a leak).

Design (region-stack frame model, encapsulated in NounSlab so Ut.slab stays a single &mut NounSlab):
- H7-A NounSlab becomes a stack of regions {slabs, allocation_start, allocation_stop}: current = top. push_frame() moves current onto a parents stack and starts a fresh region; allocations always target current (top). pop_frame_preserving(&mut roots): for each root, copy its TOP-REGION-resident nodes into the parent region (append at parent frontier; leave nodes already in any senior region untouched, via a junior test = "ptr in top region's slabs"), with forwarding-pointer dedup like NockStack noun_preserve; then dealloc the top region and make parent current. Reuses existing checkpoint/rewind/copy_into machinery. Zero-frame case is byte-identical to today. Synthetic test: build shared in keep, push, build result referencing shared + new junior, pop-preserve, assert result valid after pop AND shared not duplicated.
- H7-B Frame generation: Ut gains cache_gen:u64, bumped on every frame pop (scratch addresses recycled). Caches that hold scratch-resident values store (gen,value); lookups require gen==cache_gen (stale gens are dead -> no false-hit, no dangling read). Keep-valued caches (lazy_resolvers, core_mint cache) are NOT gen-tagged.
- H7-C Wire the per-arm frame: in build_arms_battery_from_map, bracket build_arm_formula_direct with push_frame / pop_frame_preserving([formula]); preserve the lazy resolver cached formula (mod.rs ~5016) into keep on insert; bump cache_gen on pop. Battery cons stays in caller (keep). core_type_lazy already keep (built before the walk).
- H7-D Validate: synthetic mutually-recursive-core byte-exact test (mirror the validated => synthetic), then real giant-core mint; gate on jam-diff byte/dir-hash parity for all six kernels; measure RSS + wall vs honk-138-parity baseline.

Risk controls: contained to slab.rs (region machinery) + a small set of Ut sites (frame brackets + gen-tag wrappers); zero-frame default preserves current behavior; every stage behind a byte-exact parity gate; WIP committed per green stage so it is reviewable and revertible.

## H7 frame-arena — built, byte-exact, but does NOT bound the giant core (2026-06-16)

Status after implementing the full per-arm frame arena (opt-in HONK_FRAME_ARENA):

WORKS (committed):
- NounSlab region stack + pop_frame_preserving + copy_to_base primitives (unit-tested).
- Per-arm framing wired into build_arms_battery_from_map; cache invalidation on pop; copy_to_base for whole-compile-lifetime stores (fan-leg id tables, lazy resolvers, interned seminoun singletons, AST caches handled by clear).
- BYTE-EXACT at real scale: the dumbnet kernel compiled framed (which natively mints prelude arms add-all/turn/etc. + the kernel's cores) is byte-identical to the default path. ut synthetic frame-arena tests (multi-arm cross-ref + recursion + fan-leg, wet/loop) green.

DOES NOT MEET THE GOAL (measured):
- Giant-core native mint (HONK_NATIVE_PARITY --arbitrary hoon-138), peak RSS @90s: unframed 6.26 GB vs framed 15.16 GB. Framing makes memory ~2.4x WORSE, and is ~3.5x slower; the full --arbitrary mint also still panics (a remaining dangling ref on a path the dumb kernel doesn't hit).

WHY (root cause, now data-backed from the frame-arena direction):
The giant-core blowup is dominated by PRESERVED cross-core structure, not reclaimable per-arm scratch. Specifically mint_core embeds the whole subject/context into each core's type (subject-deepening, the O(N^2) hypothesis). That structure is cross-arm/cross-core referenced, so it MUST survive frame pops — the frame arena copies it to base via copy_to_base, and copy_to_base has NO cross-call dedup, so the shared subject/formulas are DUPLICATED per core/arm. Net: reclaiming transient scratch saves less than the duplicated preserved structure costs. Per-arm scratch reclamation cannot bound a blowup whose mass is in preserved, shared, un-interned structure.

CONCLUSION: bounding hoon-138's native mint requires STRUCTURAL SHARING (interning / hash-consing) of the embedded subject and cross-arm types/formulas — the same type-interning problem flagged earlier (and hard because mugs collide, so it needs unifying-equality-style structural dedup, which is expensive). The frame arena reclaims transient scratch correctly but is orthogonal to (and, via copy_to_base duplication, counterproductive against) the dominant subject-deepening cost. The frame-arena code is committed default-OFF (zero impact on the shipping embedded-prelude path) and left for review; it is the right substrate IF combined with subject sharing, but on its own it does not deliver the memory win.

## H7 frame-arena — allocation profile (2026-06-16)

Instrumented the arena (ARENA_* counters, HONK_ARENA_STATS) and profiled the framed giant-core native mint (~85s in):
  alloc=26.1GB  pop_freed=14.1GB  preserve_copied=3.05GB  copy_to_base_calls=23573  pops=2504

Findings:
1. The frame mechanism DOES reclaim — pop_freed is ~54% of gross alloc. So pop_frame_preserving works; net retained ≈ alloc - pop_freed ≈ 12 GB (matches ~15 GB RSS).
2. Only ~2,500 pops for 26 GB allocated → the bulk is allocated INSIDE a few enormous arms (the compiler arms, ++ut-class). Per-arm framing is too COARSE: one giant arm allocates GBs in a single frame, reclaimed only when that arm finally completes. To bound the peak we'd need intra-arm (per-sub-expression / per-nested-mint) reclamation.
3. Gross alloc is INFLATED by recompute: clearing the type memos on every pop (required to avoid dangling) forces re-mint/re-decode, so gross alloc balloons to 26 GB by 85s vs the unframed baseline's slower climb. Frame copies (preserve 3 GB + copy_to_base) are NOT the dominant cost — the mint's own (recompute-inflated) allocation is.

Refined diagnosis of the memory goal: the dominant cost is honk building structurally-equal type nouns without sharing (no hash-consing), compounded by cache-clear recompute. Subjects ARE shared by pointer across siblings; the blowup is structurally-equal type REBUILDS that defeat sharing. The fix is PERVASIVE bottom-up hash-consing of type construction (every ty_* constructor interns its result), with cached mugs + a pointer-equality short-circuit in the structural verify so that, once subtrees are shared, compares are O(1) amortized. The earlier interning attempt regressed (71->84s) because it interned whole cores top-down (O(core-size) mug+compare per core) rather than incrementally bottom-up — collisions then forced full O(size) compares. Pervasive bottom-up interning avoids that (shared subtrees compare by pointer). This also removes the need to CLEAR scratch-valued memos (their values become shared/non-dangling), killing the recompute inflation. It is a large, pervasive change to honk's type layer and must stay byte-exact (interning returns structurally-equal nouns, so jam output is unchanged).
