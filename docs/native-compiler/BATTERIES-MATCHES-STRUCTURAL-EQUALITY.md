Jet dispatch has two gates: the warm-table lookup keyed on the arm formula (which find_jet's normalization made hint-blind), and Batteries::matches, which verifies the entire ancestry of the calling core — battery at each level, parent axis walk, terminating at the registered root core — against the battery nouns recorded in the cold state. Making the first gate hint-blind without the second would be useless: you'd find the jet candidate and then reject it at verification. honk needs the second gate hint-blind because the batteries it's matching come from different producers at different times — the embedded honc-cold-138.jam asset on one side, honk's natively-minted (or hoonc-jam-cued) cores on the other — and %spot hints embed absolute source positions into battery nouns, so the two sides are equivalent code but unequal nouns. The fallback only fires when plain unifying equality fails, i.e., exactly when the nouns genuinely differ, and it answers "do they differ only by transparent hints?"

What diverges, concretely

The cold state honk loads (load_cold_state/install_musk_cold_state from EMBEDDED_HONC_COLD_138_JAM) records battery nouns frozen at asset-build time, by whatever honk revision ran just honc-cold-138-asset. At runtime those recorded batteries get compared against cores from three other provenances:

- honk's native mint output — which emits %spot hints for Hoon::Dbug nodes, with toggles (include_dbug_spot, strip_dbug_wrapper_noun) that differ by mode and have changed across honk revisions;
- hoonc-compiled jams (wrapper assets, kernel jams) — hoon/common/hoon.hoon contains six !: markers, so prelude batteries genuinely carry %spot hints with file/line/column baked in; the hardcoded parity coordinates in construct_exact_wrapper_batteries ((561,8), (988,10)…) show exactly how position-sensitive these nouns are;
- re-minted prelude cores when the source isn't byte-identical to the canonical embedding.

Any source drift, dbug toggle, or revision skew between asset build and runtime shifts a %spot clue somewhere in a battery, and exact-equality matching breaks. This very branch moved hoonc.hoon by 252 lines — every recorded battery whose code transits those wrappers changed noun identity while staying semantically identical.

The three failure modes it prevents (per call site)

1. Per-dispatch jet loss — warm.rs:586. After a warm hit, matches walks the calling core's battery chain against the recorded one. A hint mismatch anywhere in the chain → NoJet → the arm runs soft. For honk that means soft-interpreting jetted compiler arms — including inside musk's mack, the ^~ constant-folding path that runs through nockvm interpret against the musk cold state on every fold. (The same branch's op_budget/set_alloc_floor_budget exist for exactly this mack path — it's all one package.)

2. Registration cascade — cold.rs:1128,1177. When a %fast hint fires, registering core C requires matching C's parent against an already-registered hierarchy via battery_list.matches(parent). The immediate parent battery is found by exact HAMT lookup, but matches then walks the grandparent-and-up chain against recorded batteries. One hint divergence in the ancestry → Error::NoParent (the "could not match parent battery at given axis" flog) → every jet below that core is lost, silently. The dedup check at cold.rs:1103 similarly needs hint-blind matching to avoid re-registering equivalent cores under diverged paths.

3. The root as global single point of failure — core_eq_ignoring_battery_hints (cold.rs:464). Every Batteries chain terminates at the registered root core (the outermost hoon.hoon core), compared as a whole. Since hoon.hoon's outer battery carries !: spot hints, any position drift changes the root battery noun — and without hint-blindness, every matches() walk in the entire system fails at the top. The fix splits the root comparison: battery hint-blind (it's code), payload exact via plain unifying equality (it's data — kernel version constants etc.; matching across different payloads would be wrong).

It's a precise equivalence, not a fuzzy match

nock_formula_eq_ignoring_transparent_hints (cold.rs:278) is careful about what it does not relax: opcode 0 axes and opcode 1 constants must be exactly equal; the axis in opcode 9 and the edit axis in opcode 10 are exact; opcode 11 hint tags are exact and non-transparent clues compare as formulas; only formula-shaped positions recurse, and only %hand/%hunk/%lose/%mean/%spot wrappers are stripped. So it computes "same Nock modulo debug/trace hints" — it can't accidentally match semantically different code. That precision is why it's a recursive interpreter over formula structure rather than a generic tree compare, which is also where the cost comes from.

Why it's expensive as written, and what to keep

Two compounding choices: it tries unifying_equality at every node as a fast path (good when subtrees are truly identical and stack-resident — they unify and later compares are pointer-fast), and nothing caches a successful hint-blind verdict. The trouble is that the cases this code exists for — hint-divergent pairs, and slab/PMA-resident nouns — can never be unified into pointer equality (they're different nouns, or live in memory the readonly-range machinery forbids rewriting). So the match never gets cheaper: every dispatch through a hint-divergent core re-pays the full structural walk, with a unifying-equality attempt per node. The design implicitly assumed verification happens at compile-scale cadence; under hoonc's interpreter-scale dispatch the walk lands in the hot loop.

For the rebase, the invariant to preserve is: jet verification and %fast registration must accept cores whose batteries differ from registered ones only by transparent hints, with payloads/axes/constants exact — that's load-bearing for honk's jets firing at all, for musk's constant folding, and for cold-state assets surviving source drift. The implementation freedom is the same as the other two items: the verdict is stable per (core battery identity, registered battery), so a small verified-pair cache — or normalizing batteries once at registration/cue time and comparing stripped forms — preserves the semantics without re-walking battery trees on every dispatch.
