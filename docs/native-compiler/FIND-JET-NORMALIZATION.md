The find_jet normalization (and its siblings in Warm::init and Batteries::matches) makes jet dispatch invariant to transparent hints (%spot/%mean/%hand/%hunk/%lose). honk needs this because the batteries and arm formulas it builds natively differ from the ones recorded in its embedded cold state only by these hint wrappers — and nockvm's jet matching is exact-noun-equality on both the formula (warm HAMT key) and the battery chain. Without hint-blind matching, honk's jets silently never fire and every interpret() call honk makes runs fully soft, which is a far worse performance cliff for honk than the per-miss traversal cost. It's a honk-correctness-and-performance change whose cost model assumed honk's workload, and hoonc pays for it as collateral.

The mechanics that force it

How honk gets jets at all. honk doesn't boot a kernel and replay %fast hints organically the way hoonc does. It embeds a pre-serialized cold state — honc-cold-138.jam, captured once from evaluating the canonical hoon-138 prelude — cues it at startup, and runs Warm::init over it (honk.rs:851-866, load_cold_state at honk.rs:2954). The justfile's honc-cold-138-asset recipe is the producer side: it runs honk itself with --dump-wrapper-assets to regenerate that jam. So honk's entire jet table is keyed on battery/formula nouns frozen at asset-build time, then matched against cores honk reconstructs natively at run time.

Why the nouns drift: %spot hints are baked into code, with positions. honk's native +mint port emits %spot hints into the formulas it generates (ut/mod.rs:7545-7556, mint_dbug at ut/mod.rs:3608), and the comment at ut/mod.rs:2342 is explicit: "mint returns formula nouns with %spot hints, so cache keys must include debug spots." A %spot clue embeds the source file path and exact line/column span. The smoking gun for how brittle this is: construct_exact_wrapper_batteries (honk.rs:2638) hand-builds "the exact tiny wrapper nouns produced by hoonc.hoon" with hardcoded coordinates — hoonc_spot_formula(slab, 561, 8, 561, 9, …), (988, 10)-(988, 14), etc. — just to achieve parity with hoonc's output for one test. Any source drift, any dbug-mode toggle (new_with_dbug_spots(false) vs true), or any difference between honk's native mint and the Hoon-compiled mint that produced the cold state shifts these spans, producing batteries that are semantically identical but not noun-equal.

Where exact equality bites, twice. Jet dispatch has two equality gates, and the branch had to relax both symmetrically:

1. The warm table is a HAMT keyed by the arm formula noun. A %spot wrapper anywhere in the formula → different noun → lookup miss → no jet. Hence the pair: insert_with_transparent_hints (warm.rs:618) registers each jet under both the original and the hint-stripped formula, and find_jet (warm.rs:664) retries a miss with the hint-stripped query. Together they implement "match iff the normalized forms agree" — registration-side normalization alone can't cover a query whose hints sit at different positions than the registered copy's.

2. Even on a formula hit, Batteries::matches walks the parent chain comparing battery nouns via unifying equality. honk's natively built cores fail that against the cold state's cued batteries for the same reason — and worse, a slab-built battery and a cued battery can never be unified into pointer equality, so without battery_eq_ignoring_hints/core_eq_ignoring_battery_hints (cold.rs:488, cold.rs:464) the mismatch is permanent. The new nockvm test batteries_match_ignores_transparent_hints_in_battery_formulas documents exactly this scenario: a registered hint-free battery matched by a query battery with a %spot-wrapped arm.

Why the sham_hints gates had to come out of the interpreter. honk builds nockvm with sham_hints on (honk's Cargo.toml). On master, that feature disabled Work9 jet dispatch and %fast/cold registration entirely. honk needs both halves: %sham name-dispatch for its prelude bring-up, and the real cold/warm pipeline — otherwise the embedded cold state would be dead weight (nothing would ever consult it), and the honc-cold-138-asset recipe couldn't even produce it (dumping cold state requires %fast registration to be active). The related sham_jet_name fix ("Peel [%hint clue formula] wrappers (eg, %spot in debug mode)", interpreter.rs:1941) is the same disease in the %sham path: in debug mode the inner [1 jet-name] formula gets %spot-wrapped, so the old fixed-shape destructuring read the wrong noun and sham jets silently stopped matching.

The same theme explains the neighboring changes. honk's nouns live in NounSlabs and the PMA, where unification is either forbidden or impossible — that's why noun_equality exists ("suitable for allocators that don't support unification (e.g., Pma, NounSlab)", ext.rs:131), why jet_dor needed it (slab nouns are structurally equal but never pointer-equal, so master's raw_equals-only head check took the wrong branch and mis-ordered honk's maps), why unifying_equality grew readonly-range awareness (zero-copy mack over slab-resident subjects must not have unification rewrite into slab memory — the mem.rs comments say exactly this), and why op_budget/set_alloc_floor_budget exist (honk's musk constant-folder needs bounded interpretation of possibly-divergent folds, "matching hoonc's behavior of abandoning infeasible folds"). The Context::save/restore ColdMem fix is the same family: honk does isolated evaluations, and master's restore only reset the Cold pointer while register mutates through it, so rollback didn't actually roll back.

The judgment call embedded in it

The design optimizes for honk's failure mode: for honk, a jet miss on a compiler arm (+mint, +nest, +mull against the cold state's ut core) means soft-interpreting the Hoon compiler — orders of magnitude. Paying O(formula) on misses to guarantee hint-invariant hits is a great trade in a workload where the important lookups hit. hoonc inverts that assumption — its steady state is millions of legitimate misses on unjetted arms — and the miss path is exactly where the new cost lives, uncached, with the normalized copy re-allocated and re-mugged per call.

So for the rebase: the invariant to preserve is "jet matching is transparent-hint-blind on both formula and battery" (plus the %sham peeling and ungated cold/warm under sham_hints) — that's load-bearing for honk. The part that isn't load-bearing is where the normalization cost is paid: nothing about honk's requirement demands normalizing on every miss; it demands that normalized forms be comparable, which is compatible with caching normalized formulas (e.g., memoized per battery/formula identity) or keying the warm table by stripped formulas outright.

# Resolution (2026-06-12)

Hint-blind jet matching is now opt-in via `JetDispatchMode { Exact, HintBlind }` on `Context` (crates/nockvm/rust/nockvm/src/jets.rs). hoonc and nockchain dispatch `Exact` — byte-for-byte master behavior, no normalization on misses, single-insert `Warm::init`, unifying-equality battery matching. honk's eval and musk contexts dispatch `HintBlind`, preserving the invariant documented above, and `find_jet` now memoizes normalized-fallback hits by inserting a warm alias keyed by the raw query formula (guarded against frame-local formulas), so honk's steady-state dispatch is exact-hit fast after the first divergent call per arm.
